# Step 5 — 빈 화면 없애기 · 표면 대비 벌리기

사용자 피드백: **"세련된지 모르겠는데 전혀."**

## 앞선 4 step이 놓친 것

Step 1~4는 전부 **색·간격·상태**였다. 대비를 1.54:1에서 9.94:1로 올렸고
토큰을 정리했고 anti-slop 카드를 없앴다. 전부 측정 가능한 것이었고 전부 통과했다.

**레이아웃은 한 번도 건드리지 않았다.** 그래서 화면 구성은 before와 같았다 —
1680×930 창에 400×250짜리 콘텐츠 섬 하나, 나머지 90%가 빈 판.
비어 있는 것은 "미니멀"이 아니라 **"미완성"**으로 읽힌다.

`design-bounce`의 판정자 분리가 여기서 실패했다. 구현자와 판정자가 같은 나였고,
**측정 가능한 것만 보고 `success`라고 적었다.** 트랙 A/B 모두 통과했지만
사용자가 요구한 "세련됨"은 두 트랙 어디에도 없었다.

## 한 것

**빈 시작 화면 → 정보 화면.** 스캔 없이 즉시 아는 것만 담았다:
- 디스크 현황 카드 (`VolumeUsage`, 32pt 수치 + 막대)
- **"Sweep이 보는 곳"** — 허용 루트 6군데와 각각이 무엇인지.
  파일을 지우는 앱에서 "무엇을 건드리는지"는 첫 화면에 있을 값이다.
  세션 초반에 사용자가 직접 물었던 것이기도 하다("정리 범위가 어떻게 됨?").

## 잡은 버그 — 테스트가 코드와 같이 틀렸다

임시 컨테이너 묶기가 안 먹어 `/var/folders/mg/h7rv...gn/C`, `.../T` 두 줄이
원시 경로로 노출됐다. 코드가 `/private/var/folders/` 접두사를 봤는데
실제 경로는 `/var/folders/`였다 (`/private`는 심볼릭 링크라 있을 수도 없을 수도 있다).

**테스트도 같은 잘못된 접두사를 써서 공허하게 통과했다.**
→ 접두사 판단을 테스트 안 헬퍼 한 곳으로 모으고,
   `#expect(!rawTemps.isEmpty)`로 "검사 대상이 실제로 있는지"를 먼저 확인하게 했다.
   TC가 아무것도 안 걸러도 통과하는 상태를 막는다.
