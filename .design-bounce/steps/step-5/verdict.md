# step-5 — 묶음 기준을 출처에서 판단으로

## 잘된 점

- 섹션이 "다시 만들 수 있음 / 확인 필요 / 보호됨 · 선택 불가"로 바뀌었다.
  훑기만 해도 고를 수 있다 — 예전에는 "Xcode · 시뮬레이터" 안에
  다시 만들 수 있는 것과 심사 제출본이 섞여 있어 하나씩 열어 봐야 했다
- **스캐너에 새 분류를 넣지 않았다.** `safety`가 이미 그 판단이고,
  독 라벨도 같은 말을 쓰고 있었다 — 같은 개념을 두 벌로 만들지 않았다
- 스마트 스캔은 카테고리 유지. 거기서는 어느 기능이 얼마를 찾았는지가 정보다

## 트랙 A (명세 준수)

| 항목 | 명세 | 실제 | |
|---|---|---|---|
| 묶음 기준 | 판단 기준 | `safetyGroups` | ✅ |
| 이름 | "다시 받을 수 있음 / 원본 자료" | "다시 만들 수 있음 / 확인 필요 / 보호됨" | ⚠️ |
| 순서 | 안전한 것부터 | `SafetyLevel` 정렬 | ✅ |

> 이름이 핸드오프와 다르다. 핸드오프는 큰 파일 화면 기준("다시 받을 수 있음 / 원본 자료")이고
> 여기는 **모든 기능이 공유하는 세 등급**이다. 정크에 "원본 자료"는 뜻이 없고,
> 기능마다 이름을 따로 두면 같은 등급이 화면마다 다르게 불린다.
> 독의 분포 라벨과도 한 벌로 맞췄다.

## 트랙 D (프로토타입 대조)

1. ✅ 판단 기준 묶기
2. `[Medium-Priority]` 이름이 기능별로 특화되지 않는다 (위 근거)
3. `[High-Priority]` 툴바 통합이 남아 있다
